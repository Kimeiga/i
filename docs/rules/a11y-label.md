# `a11y/label`

> Form field has no label

| | |
| --- | --- |
| Severity | critical |
| Layer | Runtime accessibility (axe-core in a real browser) |
| Status | enabled by default |

## What it detects

A form control has no associated label, so its purpose is not announced and clicking the visible text does not focus it. A placeholder is not a label: it disappears on focus.

## Why it matters

This maps to WCAG 2.1 success criterion 1.3.1 Info and Relationships (Level A) and WCAG 2.1 success criterion 3.3.2 Labels or Instructions (Level A) and WCAG 2.1 success criterion 4.1.2 Name, Role, Value (Level A). EN 301 549, the harmonised European standard referenced by the European Accessibility Act, incorporates WCAG 2.1 Level AA in full, so a failure here is a failure against the standard European regulators assess against. See [regulatory context](../regulatory-context.md); this is not legal advice.

## How to fix it

Each finding carries the specific fix for that instance in its `help` field.

## How to suppress it

```ts
// attest-disable-next-line a11y/label -- why this instance is intentional
```

Or for a whole file:

```ts
// attest-disable-file a11y/label -- why this file is intentional
```

Or in `attest.config.json`, to turn the rule off everywhere:

```json
{
  "rules": {
    "a11y/label": "off"
  }
}
```

Suppressed findings are **recorded in the report**, with the reason you gave. That is deliberate: a suppression is a decision, and the evidence trail keeps decisions. It is not a way to make a finding disappear from the record.
