# `a11y/heading-order`

> Heading levels skip a level

| | |
| --- | --- |
| Severity | moderate |
| Layer | Runtime accessibility (axe-core in a real browser) |
| Status | enabled by default |

## What it detects

Heading levels increase by more than one, so the document outline screen reader users navigate by has gaps in it. Note that no WCAG success criterion requires sequential heading levels — axe-core classifies this as a best practice and so do we.

## Why it matters

No published standard enumerates this requirement. It is reported because it causes a defect that is expensive to diagnose after the fact and cheap to avoid at review time.

## Standards

| Framework | Reference | |
| --- | --- | --- |
| Attest property | axe-best-practice | [axe-core best practice, not required by any WCAG success criterion](https://dequeuniversity.com/rules/axe/4.13) |

`privacy-property` means this is our own definition, not a numbered requirement in a published standard. We label it that way rather than citing a regulation that does not say it.

## Code that triggers it

`fixtures/a11y-runtime/heading-order/triggering.html`

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>Heading order</title>
  </head>
  <body>
    <main>
      <h1>Heading order</h1>
      <h3>Delivery options</h3>
      <p>The heading above skips from level 1 to level 3.</p>
    </main>
  </body>
</html>
```

## How to fix it

Each finding carries the specific fix for that instance in its `help` field. Deque's page for the underlying axe-core rule has the full treatment: https://dequeuniversity.com/rules/axe/4.13.

## How to suppress it

```ts
// attest-disable-next-line a11y/heading-order -- why this instance is intentional
```

Or for a whole file:

```ts
// attest-disable-file a11y/heading-order -- why this file is intentional
```

Or in `attest.config.json`, to turn the rule off everywhere:

```json
{
  "rules": {
    "a11y/heading-order": "off"
  }
}
```

Suppressed findings are **recorded in the report**, with the reason you gave. That is deliberate: a suppression is a decision, and the evidence trail keeps decisions. It is not a way to make a finding disappear from the record.
