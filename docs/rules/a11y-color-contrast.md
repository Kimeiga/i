# `a11y/color-contrast`

> Text contrast below the minimum ratio

| | |
| --- | --- |
| Severity | serious |
| Layer | Runtime accessibility (axe-core in a real browser) |
| Status | enabled by default |

## What it detects

Text does not meet the 4.5:1 contrast ratio against its background (3:1 for large text). This is measured against the computed colours of the rendered page, which is why it only appears in a runtime scan.

## Why it matters

This maps to WCAG 2.1 success criterion 1.4.3 Contrast (Minimum) (Level AA). EN 301 549, the harmonised European standard referenced by the European Accessibility Act, incorporates WCAG 2.1 Level AA in full, so a failure here is a failure against the standard European regulators assess against. See [regulatory context](../regulatory-context.md); this is not legal advice.

## How to fix it

Each finding carries the specific fix for that instance in its `help` field.

## How to suppress it

```ts
// attest-disable-next-line a11y/color-contrast -- why this instance is intentional
```

Or for a whole file:

```ts
// attest-disable-file a11y/color-contrast -- why this file is intentional
```

Or in `attest.config.json`, to turn the rule off everywhere:

```json
{
  "rules": {
    "a11y/color-contrast": "off"
  }
}
```

Suppressed findings are **recorded in the report**, with the reason you gave. That is deliberate: a suppression is a decision, and the evidence trail keeps decisions. It is not a way to make a finding disappear from the record.
