# `a11y/frame-title`

> Frame has no title

| | |
| --- | --- |
| Severity | serious |
| Layer | Runtime accessibility (axe-core in a real browser) |
| Status | enabled by default |

## What it detects

An <iframe> has no title attribute, so it is announced only as "frame" and a screen reader user cannot tell whether it is worth entering.

## Why it matters

This maps to WCAG 2.1 success criterion 4.1.2 Name, Role, Value (Level A) and WCAG 2.1 success criterion 2.4.1 Bypass Blocks (Level A). EN 301 549, the harmonised European standard referenced by the European Accessibility Act, incorporates WCAG 2.1 Level AA in full, so a failure here is a failure against the standard European regulators assess against. See [regulatory context](../regulatory-context.md); this is not legal advice.

  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />

## How to fix it

Each finding carries the specific fix for that instance in its `help` field.

## How to suppress it

```ts
// attest-disable-next-line a11y/frame-title -- why this instance is intentional
```

Or for a whole file:

```ts
// attest-disable-file a11y/frame-title -- why this file is intentional
```

Or in `attest.config.json`, to turn the rule off everywhere:

```json
{
  "rules": {
    "a11y/frame-title": "off"
  }
}
```

Suppressed findings are **recorded in the report**, with the reason you gave. That is deliberate: a suppression is a decision, and the evidence trail keeps decisions. It is not a way to make a finding disappear from the record.
