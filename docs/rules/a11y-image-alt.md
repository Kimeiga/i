# `a11y/image-alt`

> Image has no text alternative

| | |
| --- | --- |
| Severity | critical |
| Layer | Runtime accessibility (axe-core in a real browser) |
| Status | enabled by default |

## What it detects

An <img> element has no alt attribute, so a screen reader announces the file name or nothing at all. Decorative images need alt="" to be skipped; informative ones need text that conveys what the image conveys. Only a person can judge which this is, so the fix is never automatic.

## Why it matters

This maps to WCAG 2.1 success criterion 1.1.1 Non-text Content (Level A). EN 301 549, the harmonised European standard referenced by the European Accessibility Act, incorporates WCAG 2.1 Level AA in full, so a failure here is a failure against the standard European regulators assess against. See [regulatory context](../regulatory-context.md); this is not legal advice.

## How to fix it

Each finding carries the specific fix for that instance in its `help` field.

## How to suppress it

```ts
// attest-disable-next-line a11y/image-alt -- why this instance is intentional
```

Or for a whole file:

```ts
// attest-disable-file a11y/image-alt -- why this file is intentional
```

Or in `attest.config.json`, to turn the rule off everywhere:

```json
{
  "rules": {
    "a11y/image-alt": "off"
  }
}
```

Suppressed findings are **recorded in the report**, with the reason you gave. That is deliberate: a suppression is a decision, and the evidence trail keeps decisions. It is not a way to make a finding disappear from the record.
