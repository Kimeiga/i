# `a11y/list-structure`

> List contains elements that are not list items

| | |
| --- | --- |
| Severity | moderate |
| Layer | Runtime accessibility (axe-core in a real browser) |
| Status | enabled by default |

## What it detects

A <ul> or <ol> has children other than <li>, which breaks the list semantics screen readers use to announce "list of 5 items" and to navigate between them.

## Why it matters

This maps to WCAG 2.1 success criterion 1.3.1 Info and Relationships (Level A). EN 301 549, the harmonised European standard referenced by the European Accessibility Act, incorporates WCAG 2.1 Level AA in full, so a failure here is a failure against the standard European regulators assess against. See [regulatory context](../regulatory-context.md); this is not legal advice.

## How to fix it

## How to suppress it

```ts
// attest-disable-next-line a11y/list-structure -- why this instance is intentional
```

Or for a whole file:

```ts
// attest-disable-file a11y/list-structure -- why this file is intentional
```

Or in `attest.config.json`, to turn the rule off everywhere:

```json
{
  "rules": {
    "a11y/list-structure": "off"
  }
}
```

Suppressed findings are **recorded in the report**, with the reason you gave. That is deliberate: a suppression is a decision, and the evidence trail keeps decisions. It is not a way to make a finding disappear from the record.
